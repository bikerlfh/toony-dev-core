# Issue Artifacts Design

**Date**: 2026-03-06
**Status**: Approved

## Overview

New `IssueArtifact` model to store plans, design docs, technical specs, and other documents generated by Claude Code during issue development. Artifacts are viewable in a dedicated listing page, within issue detail, and within agent task detail.

## Data Model

App: `projects/` (alongside Issue, IssueComment, IssueActivity)

```python
class ArtifactType(models.TextChoices):
    PLAN = "PLAN", "Plan"
    DESIGN_DOC = "DESIGN_DOC", "Design Doc"
    TECHNICAL_SPEC = "TECHNICAL_SPEC", "Technical Spec"
    TEST_PLAN = "TEST_PLAN", "Test Plan"
    OTHER = "OTHER", "Other"

class ArtifactStatus(models.TextChoices):
    DRAFT = "DRAFT", "Draft"
    PENDING_APPROVAL = "PENDING_APPROVAL", "Pending Approval"
    IN_REVIEW = "IN_REVIEW", "In Review"
    APPROVED = "APPROVED", "Approved"
    REJECTED = "REJECTED", "Rejected"
    REVISION_REQUESTED = "REVISION_REQUESTED", "Revision Requested"
    SUPERSEDED = "SUPERSEDED", "Superseded"

class IssueArtifact(BaseModel):  # UUID pk, created_at, updated_at
    issue = ForeignKey(Issue, CASCADE, related_name="artifacts")
    agent_task = ForeignKey(AgentTask, CASCADE, related_name="artifacts")
    title = CharField(max_length=500)
    artifact_type = CharField(max_length=20, choices=ArtifactType.choices)
    content = TextField()  # Markdown
    status = CharField(max_length=20, choices=ArtifactStatus.choices, default=DRAFT)
    session_id = CharField(max_length=255)
    requires_approval = BooleanField(default=False)
```

### Field Decisions

- `issue`: FK obligatory, CASCADE — artifact always belongs to an issue
- `agent_task`: FK obligatory, CASCADE — artifact always born from a task
- `content`: Single TextField with Markdown, rendered on frontend
- `session_id`: Own field (not derived from AgentTask) because a task can have multiple sessions via resume/reply

## Status Transitions

```
DRAFT -> PENDING_APPROVAL
PENDING_APPROVAL -> IN_REVIEW, APPROVED, REJECTED
IN_REVIEW -> APPROVED, REJECTED, REVISION_REQUESTED
REVISION_REQUESTED -> PENDING_APPROVAL, DRAFT
APPROVED -> SUPERSEDED
REJECTED -> DRAFT
SUPERSEDED -> (terminal)
```

### Automatic Behaviors

- If `requires_approval=True` on creation, status starts as `PENDING_APPROVAL` (not DRAFT)
- When a new artifact of the same `artifact_type` is created for the same `issue`, the previous `APPROVED` artifact of that type is automatically marked `SUPERSEDED`
- Transition validation enforced in the service layer

## API Endpoints

### Nested under Issue (CRUD)

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/api/projects/{id}/issues/{issue_id}/artifacts/` | List artifacts for an issue |
| POST | `/api/projects/{id}/issues/{issue_id}/artifacts/` | Create artifact |
| GET | `/api/projects/{id}/issues/{issue_id}/artifacts/{artifact_id}/` | Artifact detail |
| PATCH | `/api/projects/{id}/issues/{issue_id}/artifacts/{artifact_id}/` | Update artifact |
| DELETE | `/api/projects/{id}/issues/{issue_id}/artifacts/{artifact_id}/` | Delete artifact |

### Global (for listing page)

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/api/artifacts/` | List all artifacts (filters: `artifact_type`, `status`, `issue_id`, `agent_task_id`) |
| GET | `/api/artifacts/{id}/` | Artifact detail shortcut |

## Frontend

### TypeScript Types

```typescript
// frontend/types/artifacts.ts

type ArtifactType = "PLAN" | "DESIGN_DOC" | "TECHNICAL_SPEC" | "TEST_PLAN" | "OTHER"

type ArtifactStatus = "DRAFT" | "PENDING_APPROVAL" | "IN_REVIEW" | "APPROVED"
  | "REJECTED" | "REVISION_REQUESTED" | "SUPERSEDED"

interface ArtifactList {
  id: string
  title: string
  artifact_type: ArtifactType
  status: ArtifactStatus
  requires_approval: boolean
  issue_id: string
  agent_task_id: string
  created_at: string
}

interface ArtifactDetail extends ArtifactList {
  content: string
  session_id: string
  issue: { id: string; identifier: string; title: string }
  agent_task: { id: string; title: string; status: AgentTaskStatus }
  updated_at: string
}
```

### Routes

| Route | Description |
|-------|-------------|
| `/artifacts` | Global listing page (sidebar under AI Studio) |
| `/artifacts/[id]` | Artifact detail (Markdown render + metadata sidebar) |

### Listing Page (`/artifacts`)

- Table: title, type badge, status badge, issue link, task link, date
- Filters: `artifact_type`, `status`
- Uses `GET /api/artifacts/`

### Detail Page (`/artifacts/[id]`)

- Header: title, type badge, status badge, action buttons (approve/reject/request revision based on current status)
- Main panel: rendered Markdown content
- Sidebar: issue link, task link, session_id, requires_approval flag, timestamps

### Embedded in Existing Pages

1. **Issue detail** (`/projects/[id]/issues/[issueId]`): New "Artifacts" tab alongside Comments and Activity — lists artifacts with status badges and links to detail
2. **Agent Task detail** (`/toony-agents/[id]/tasks/[taskId]`): "Artifacts" section showing artifacts generated by that task
